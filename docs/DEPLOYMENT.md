## Backend on Render (Blueprint)

1. Push this repository to GitHub (public).
2. In Render: **New → Blueprint**, connect the GitHub repo, pick the branch, and apply `render.yaml`.
   This creates:
   - `pms-db` — free PostgreSQL
   - `pms-api` — Node web service in `backend/`
     - build: `npm ci --include=dev && npm run build && npm run db:deploy` (compiles TypeScript and applies Prisma migrations)
     - start: `npm start`
     - health check: `/api/health`
3. Environment variables (set by the Blueprint):

   | Variable | Value |
   |---|---|
   | `NODE_ENV` | `production` (enables `trust proxy` so rate limiting sees the real client IP, hides error internals) |
   | `DATABASE_URL` | from `pms-db` |
   | `JWT_SECRET` | generated by Render (random) |
   | `JWT_EXPIRES_IN` | `1h` |
   | `CORS_ORIGIN` | `http://localhost:5173` initially → **change to the Vercel URL** after the web deploy |
   | `AUTH_RATE_LIMIT_WINDOW_MS` / `AUTH_RATE_LIMIT_MAX` | `900000` / `10` |

4. Verify:
   ```bash
   cd backend && ./scripts/smoke.sh https://<your-service>.onrender.com
   ```

### Notes
- Render's free web service sleeps when idle; the first request can take ~30–60 s. Open `/api/health` before a demo.
- Render's free PostgreSQL has a limited lifetime. Alternative: create a free database on **Neon**, and set `DATABASE_URL` on the service to the Neon connection string (append `?sslmode=require`) instead of using `pms-db`.
- Demo data (optional): from your machine, `DATABASE_URL=<external connection string> npm run db:seed` — creates only fake `@example.com` users.
